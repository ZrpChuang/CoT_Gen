# 工作区整理方案（2026-10-10）

本轮先列用途和优先级，再整理核心内容；确定冗余的直接删除，涉及唯一实验记录的列入 REVIEW.md。

## 盘点结果

全工作区有 112,622 个普通文件（不计 .git 和符号链接），25,760 个目录；79 个目录的直接普通文件超过 10 个。baseline_method 为 270 个文件，顶层 20 个文件。auto_research 为 111,845 个文件，研究根目录直接放了 101 个文件。

这些数量来自整理前快照。FULL_INVENTORY.tsv.gz 为逐文件清单，列出原路径、目标路径、用途、优先级和处理决定。FILES.md 单独列出 baseline 的每个文件，便于阅读。

## 保留顺序

1. P0：总表和结论；逐题回答、裁判记录、指标、数据/代码哈希、训练完成记录；四方法 CoT 和训练集；统一运行入口及训练/评测核心代码。
2. P1：实验配置、提示词、原始训练数据与固定测试集、核心代码测试、可用于定位问题的历史日志。
3. P2：中间进度、派生汇总、旧计划和巡检快照。重复内容合并；有唯一信息的先 review。
4. P3：可自动重建的字节码、空日志、已停止任务的空 advisory lock、已确认相同的重复文件。直接删除或合并。

## baseline 目标结构

将每个目录的直接条目（普通文件、目录、链接）也控制在 10 个以内，避免仅满足“文件数”而仍难阅读。根目录保留如下 10 项：

```text
baseline_method/
├── README.md                 入口与使用方法
├── pipeline.py               唯一调度入口
├── core/                     9 个核心模块 + tests/
├── configs/                  配置、依赖、lint 配置、prompts/
├── docs/                     结论、逐文件用途、方案和 review
├── data/                     共享参考答案、完成标记、logs/
├── NEU/
├── SUP/
├── AUG-SUP/
└── SSR/
```

四个方法目录保留原有位置；每个目录有 3 个样本/清单文件、4 个 benchmark 目录和2个模型记录目录，共9项。各结果目录保留 responses、judgments、metrics 和生成/裁判配置。模型路径链接继续指向工作区外的产物库。

三份重复结果说明合并进 docs/RESULTS.md，保留两层表头总表、实验设置、低学习率对照和诊断。8份相同的评测来源清单合并为 configs/evaluation_sources.sha256.json；剩余8份服务记录合入 data/logs/service-history.tar.gz，冻结评测目录的 runtime/ 空目录移除。旧派生总表和短报告日志删除。

移动核心代码后同步改 settings、pipeline 和 CI 的路径；校验所有旧结果哈希、56个符号链接、40个分数以及 dry-run 跳过完成阶段的行为。

## 其余工作区的整理顺序

- 根目录：数据说明、数据统计与来源锁定清单归入 docs/data/；README 保留清晰导航。
- test_scripts：核心评测源码和原始结果保留；把 runtime 的历史日志打成有索引的压缩包，避免一个目录散放20多个文件。单次修复脚本列入 review。
- training_data / test_data：保留固定索引、清单与上游快照。第三方源码不随意改路径；如目录超过10文件，优先按原快照打包，而非拆散依赖。
- auto_research：主阅读面收敛为 README、RESULTS、阶段总结、复用工具和数据/结果索引。旧计划/审查按阶段合并；逐题缓存打包或合并为 JSONL。涉及付费结果、未完成终评恢复和源码冻结门禁，先按 REVIEW.md 决定处理范围。

## 本轮可以直接删除

- Python __pycache__ 和 .pyc：解释器自动重建。
- 空 .log：无信息量。
- phase5 transport_cache 内的 .scope.lock / .request.lock / .manifest.lock：仅在任务已停止、文件为空、超过一天、可取得非阻塞排他锁时删除；它们由代码自动创建，不包含回答、评分或运行记录。
- baseline 已确认相同的重复来源清单：保留一个集中版本；合并后的重复说明与旧生成总表删除。

实际删除数量与路径写入逐文件清单。其他文件不按名字批量删除。
